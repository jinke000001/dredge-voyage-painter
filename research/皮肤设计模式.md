# DREDGE Mac：皮肤设计与机制边界

分析日期：2026-10-16。对象为用户提供的 `Contents/`，Unity 2021.3.5f1、macOS x86_64 / arm64。包声明版本为 1.5.3，BuildInfo 和本副本原生标题实际显示 v1.5.4 prod / build 2993；兼容性以程序集 SHA-256 为准。以下机制结论来自本地资源与静态 IL，原生验证另见交付记录。

## 原版结构

| 部分 | 实际模式 | 本次沿用方式 |
|---|---|---|
| 船身与船顶 | 各 8 个色值，`_Hull_Color` / `_Roof_Color` 两个着色参数 | 新增配套颜色组合，只覆盖材质槽 0 的显示参数 |
| 船体贴图 | 主要是 16×16 色块贴图与 16×16 遮罩；低多边形模型按色块取样 | 保留原贴图、遮罩、UV、窗户和灯光，不把大幅插画硬贴到色块 UV 上 |
| 旗帜 | 7 款 256×256 图集，布面和旗杆色块共用；有透明裁切材质 | 原创旗面仅进入上部 256×180，底部 76 行保留原像素 |
| 升级与损坏 | 5 档船体；升级切对象，损坏切同一渲染器的网格 | 保留全部模型、碰撞、动画和损坏网格 |
| 装备与彩旗 | 原组件单独控制是否显示 | 不增加装备、不主动启用任何隐藏物件 |

原旗帜槽位依次为：1 绿钩、2 橙锚、3 蓝鱼、4 海盗、5 眼睛、6 海蛇、7 衔尾蛇。槽位 0 为不挂旗。船色索引与旗帜索引由原游戏的画匠对话写入存档；`has-paint-*`、`has-flag-*` 决定原版解锁。

`PlayerColorCustomizer` 序列化引用包括 10 个船体 MeshRenderer、10 个彩旗 SkinnedMeshRenderer、5 个旗帜 SkinnedMeshRenderer。复用这些引用可以随原版五档船体和损坏显示工作，不另造“功能船”。

## 旗面规格

真实 Flag 网格 UV：u = 0.00798034668…0.991210938；v = 0.305419922…0.993652344。按图像左上原点转换，约覆盖 x=2.04…253.75、y=1.63…177.81。新图覆盖上部 180 行，给双线性取样留下边缘余量；底部 76 行属于旗杆区域，保持不变。

原创源图为 1536×1024 PNG（3:2），运行时先缩为 384×256，再适配旗面区域。图案使用中心大剪影、少量高对比配色和轻微旧印刷质感，避免小字号和细碎细节。保留原旗帜网格、骨骼、材质和动画，因此不会引入一套独立飘动机制。

## 机制边界

原版航速、钓鱼效率等由 `PlayerStats` 的装备、研究、油污与能力状态计算；船舱格与耐久升级由 `UpgradeManager` / `SaveData` 管理。外观扩展不调用这些写入流程，也不写画匠对话、价格、资源、解锁变量或游戏存档。

接入只在 `PlayerColorCustomizer.RefreshBoatColors` 和 `RefreshBoatFlag` 正常返回前追加各一个回调。游戏先完成自己的操作，扩展随后通过 `MaterialPropertyBlock` 覆盖材质槽 0 的两种颜色或旗面纹理。材质槽 1 的灯光、破损网格与物理对象保持原有职责。

选择记录保存在独立的 `JinkeDredgeSkins` 设置文件；游戏原索引保留合法原值。原版未挂旗时，选择自定义旗面也不会强制显示旗帜。原版配色刷新、升级后的默认配色与回到原版必须在原生验收中覆盖。
