日期：2026-10-21（北京时间）。运行组件版本 `2.3.0-mvp.1`。用户已批准新隔离副本和一次性测试档的实机验收；源码、离线检查和下述原生运行验证已执行。用户已手动确认日常游玩功能通过，并于 2026-10-21 决定结束本轮测试；未覆盖项目如实保留，不再追加本轮测试。没有读取或修改个人存档、导入个人进度、替换旧 2.2.0 app、提交或推送。

## 体验与边界

造船坞原升级树上方并列“货舱整备”和“船型外观”。船型子页提供“折线渔舟”“原版”“返回升级树”。非五级船可以查看说明，但不能改变外观或保存选择。入口只出现在原油漆匠整合 profile。

折线渔舟为程序生成的低面数船体，四档分别对应 Sturdy、Ok、Poor、Critical，以右舷局部凹陷区分。每档 618 顶点，194 个船体三角形与 12 个窗户三角形；两子网格沿用原材质槽 0/1。UV 采样原 Boat5 船壳、屋顶和中性区域；窗户使用原窗面 UV，顶点色为白色。实机近景发现原鱼竿夹座与新舱体间有支撑间隙，已在新网格加入约 8 厘米宽的托块；挂件 Transform 未变。

只拥有 Boat5 的 `DamageStateMeshes` 内容及其 `MeshFilter.sharedMesh` 引用，不更换 `BoatModelProxy`、Renderer 或材质，不缩放船体，不读写原 Mesh 顶点，不修改碰撞、浮力、航迹、泡沫、装备及挂件。

依据是原 Mac v1.5.4 / build 2993，原程序集 SHA-256：

```text
a071ffebe51514af5f661055f126a5041acda127623ee7c681c6ef2233a24729
```

原 `Boat5_Sturdy` 不可读，运行时只读取 bounds 和子网格数量检查合同。原范围为 center `(0,1.2232823,.2452915)`、extents `(.7112064,1.6060355,1.7017434)`；新网格使用独立顶点，保留 +Z 船首和原水线附近的甲板。原旗杆是独立 `FlagAccessory/FlagPole`，未随主体网格被替换；其基部约 y=1.897，与新舱顶 y=1.89 接近。这是静态资源关系，不能替代实机挂件视觉验收。

## 实现与生命周期

- `Boat5Geometry` 负责纯几何；`Boat5MeshFactory` 创建四个独立 Unity Mesh，失败时释放已生成资源。
- `Boat5Binding` 在替换前复制四档原网格列表。后续由原 `BoatSubModelToggler.OnPlayerDamageChanged` 使用新列表选态；应用和恢复时按原损伤算法立即同步当前网格，不广播伤害事件，也不改变原严重受损效果。
- `ShipAppearance.OnSaveReady` 接入现有 `Bootstrap.AfterSaveDataInit`；`VoyageRuntime.Update` 每帧核查玩家重建，`OnBoatModelChanged` 处理模型切换。首次绑定主动应用，不依赖等到下一次事件。切档、标题返回、玩家及事件单例重建均解除旧订阅并恢复旧网格，再清理生成资源。
- 真实等级必须为 5，当前激活 Proxy 必须对应玩家预制体的 Boat5。其他等级不生成或应用船型；离开 Boat5 时恢复此前拥有的隐藏 Boat5 引用，不修改其他船体。
- Weaver 的 `VoyagePainter` 固定 17 个目标、原 SHA-256/MVID 锁及白名单没有变化，没有新增 IL 补丁。模型切换用事件，重建用下一帧核查；不承诺所有场景初始化顺序下都没有一帧原网格闪现。

## 保存与恢复

仅使用原 `SaveData.stringVariables`：键 `jinke-ship-appearance-v1`，首款 ID `faceted-trawler-v1`。缺键显示原版；未知 ID 或资源不可用显示原版但保留原字符串。恢复时只有明确选择“原版”才删除该键。

选择要求隔离的 Painter profile、当前活动档、存活、停泊、允许保存且为 Boat5。资源验证和网格应用成功后才写 ID；失败保留此前选择并恢复此前显示。继续沿用原保存时机，没有为点击按钮强制保存整个游戏。

恢复用独立快照还原四档原网格，并按当前伤损选回正确原网格。不会重置船体等级、船漆、旗帜、灯开关或装备。先解除生成网格引用，再销毁生成物；若仍存活对象恢复失败，保留资源引用以避免破坏当前显示。

## 造船坞交互

`CargoRefitPanel` 是两页唯一的返回键、节点隐藏和焦点宿主；`DryDockPageState` 保证互斥并标记会话与代次。货舱确认弹窗期间拒绝底层返回及切页，旧确认回调不能跨页面重开或跨档执行。共享原版按钮、字体、本地化及明确方向导航；满级升级节点全部不可选时，新增入口仍可成为手柄默认焦点。

资源首次准备失败时不会每帧重复生成；Boat5 页面允许明确重试。隐藏/销毁只释放租用与状态，不在不可见对象上启动焦点协程。

## 下一阶段提案：Blender 精细模型

2026-10-21 用户希望由 agent 操作 Blender 制作精细船模并实装，按阶段由用户决策执行。最初仅提出路线；随后用户确认没有安装 Blender，明确授权先完成安装与接入，并允许也使用 Unity。工具准备完成后，用户选择“原版风格精致远洋渔船”，授权先做 Blender 灰模、确认后再精修和实装。用户随后明确确认灰模整体方向，授权按该造型继续精修、保持原版风格，先评审精修效果，确认后再实装。本轮只制作精修预览，不修改生产换模代码或启动新一轮游戏测试；详情见末节。

推荐保持 DREDGE 的风格化造型，通过船首、船舱、舷缘与甲板等细节提升完成度；真实比例、写实贴图或完全不同船型需先确认。以下是建议阶段，不是已批准的美术方案：

| 阶段 | agent 交付 | 用户决定 |
|---|---|---|
| 1. 确定船型与参考 | 提炼轮廓、风格、细节目标，确认工具位置或安装准备 | 选船型与风格，决定进入 Blender 制作 |
| 2. Blender 灰模 | 用简单体块制作完整比例，给出前/侧/斜视渲染；以挂点占位核对灯、鱼竿、拖网、旗杆的空间 | 确认船体轮廓与比例，或要求调整 |
| 3. 精修与四伤态预览（本轮交付） | 两款风格均获用户认可；完成两款四伤态可编辑 .blend、多角度渲染及原材质只读核查 | 确认伤态效果与原灯统一控制的材质取舍后，进入生产资源准备和实装 |
| 4. 生产资源与独立副本（本轮完成离线交付） | 两款四态、两子网格、作者法线与原创配对图集已接入；新固定身份 R2 fresh 构建通过，原十七钩子和版本锁不变；保留原版、折线渔舟及 2.2.0 | 启动前等待另行同意；新资源的实机验证尚未执行 |

现有代码依据：`Boat5MeshFactory.Create` 的主要接缝是 `Boat5Geometry.Build` 之后向 Mesh 写入顶点、UV、顶点色及两组索引；`Boat5Binding` 要求四态/两槽并只持有显示网格引用。因此建议由 Blender 导出受控网格数据，再于构建阶段转换成模型资源或数组。新增 ID 的识别和工厂选择需要小范围源码适配；不会让游戏直接读取 .blend。当前仍是建议，未实现导出器或新 ID。

优先沿用原材质槽 0（含船漆/屋顶/中性色区域）和槽 1（窗户发光），保留现有 Renderer、碰撞、浮力、特效与挂件。精模需要保留作者法线，不能直接用当前 `RecalculateNormals` 丢弃其硬边/平滑效果；导出须检查 Blender 与 Unity 的轴向、单位、三角形绕序、UV 与四态一致性。当前生成器的 1 万顶点限制不是精模预算；正式制作时另定合理网格规模。复杂原创贴图可能需要扩大材质范围，届时单独提出，不默认改变本轮合同。
