# 旗帜功能深度审查报告

- **审查日期**：2026-10-17
- **审查对象**：DREDGE 外观版 MOD 的旗帜功能全链路（IL 织入层 / MOD 运行时层 / 游戏本体契约层）
- **目标构建**：DREDGE Mac v1.5.4 build2993，发布包 `output/builds/DREDGE 外观版`（Assembly-CSharp.dll 织入产物 SHA-256 `3cfc648c…`，运行时 Jinke.DredgeSkins.dll `a2cba006…`）
- **审查方式**：纯静态审查 + 反编译交叉验证 + 独立 IL 重读 diff + 既有原生探针证据复核 + 67 项托管回归测试运行。**全程未修改任何源码。**
- **审查范围**：`src/Weaver/`、`src/CosmeticPack/`（12 个源文件）、`tools/build_local.py`、`assets/JinkeSkins/`、`research/decompiled/`、`research/evidence/`、全部构建审计 JSON。

---

## 一、总体结论

**未发现会影响游戏运行的致命或高危 bug。**

三条链路的关键安全性质均经独立证据核验通过：

| 链路 | 核心结论 |
|---|---|
| IL 织入层 | 仅改动 9,375 个方法体中的 2 个（`RefreshBoatColors` / `RefreshBoatFlag`），剥离钩子后逐字节还原原版；注入点栈平衡、不碰异常表、字段初始化时序安全、防二次织入三重防护有效 |
| MOD 运行时层 | 67 项回归测试全绿；MPB 覆盖/恢复模型、图集合成数学、色彩空间往返、资源配对释放四个最易错子系统均确认正确 |
| 游戏契约层 | 7 条本体假设全部成立（字段、着色器属性、图集尺寸、UV 布局、游戏从不写 MPB、装备机制、Renderer 生命周期均有反编译或原生探针实证） |

需要关注的问题是 **3 项中级 + 7 项低级 + 8 项提示**，全部是健壮性瑕疵、流程风险或验证覆盖缺口，在当前锁定的游戏版本上没有一条能直接破坏游戏运行。

## 二、发现清单（按严重级别）

### 中级（3 项）

**M1. `PauseUiGuard.Bind` 半初始化后永不重试，契约失配会株连整个 MOD**
- 位置：`src/CosmeticPack/PauseUiGuard.cs:34-47`、`:49-61`；触发点 `SkinController.cs:58`
- 问题：`Bind` 按序赋值，`gameInstance` 最先非空；若后续某个属性（如 `IsPlaying`）缺失则抛 `MissingMemberException`，但下次调用因 `gameInstance != null` 直接返回，留下半成品状态。此后 `IsSafe` 每次访问 `isPlaying.GetValue(...)` 都抛 NullReferenceException → `Update`/`OnGUI` catch → FailSafe → **纯 UI 契约失配导致皮肤功能整体永久停用**（皮肤本身本可继续工作）。
- 触发条件：游戏更新后 `GameManager` 缺少 `IsPlaying`/`IsPaused`/`CanUnpause`/`Input` 之一。当前 v1.5.4 全部存在（已反编译确认），属**潜伏性**问题——是全部发现中唯一"游戏小更新即可激活"的隐患。
- 影响：MOD 停用并回退原版外观；游戏本体运行不受影响。FailSafe 有 `failed` 标志限流，不刷屏。

**M2. 「实装旗帜 + 应用皮肤」这一核心场景从未原生验证**
- 证据：`research/evidence/native-probe-06/07` 两轮原生探针中 `flagId` 均为 0、5 个旗 Renderer visible=false；`交付验证.md` 的实玩反馈未逐项覆盖挂旗场景。
- 问题：旗帜功能的最终呈现路径——MPB 贴图覆盖在真实挂旗（`BoatFlagStyle>0`、FlagAccessory 激活）状态下生效、且布料动画/双面渲染视觉正常——目前只有静态推断，没有原生证据。静态推断依据是可靠的（MPB 跨材质替换存活是 Unity 语义；属性缺失静默跳过、尺寸不符抛错走 FailSafe，均无崩溃路径），但这是旗帜功能**唯一未被端到端验证的链路**。
- 影响：最坏情况为旗面显示原图或视觉异常；无崩溃、无存档风险。

**M3. `build_local.py` 不校验运行时 dll 的源码新鲜度**
- 位置：`tools/build_local.py:54-57`
- 问题：只检查 `src/CosmeticPack/bin/Release/net472/Jinke.DredgeSkins.dll` 存在，不重建、不比对源码 mtime。改了源码忘编译时，陈旧 dll 会被静默织入打包。
- 本次发布无此问题：实测 bin 产物、staging 快照、发布 app 内 dll 三方 SHA-256 完全相同，且与审计记录的 `runtimeSha256` 一致。
- 影响：未来迭代可能出现"发布包与源码不一致"的静默漂移；审计只能事后发现。

|---|---|---|---|
| L1 | `SkinAssets.cs:80` | 图集缓存上限 48 触顶即抛异常 → FailSafe **永久自杀**，重启后若再满再自杀 | 实测正常上限 21/48（7 原图×3 皮肤），仅在游戏反复重载资产包且旧贴图不销毁时可达；触顶后外观功能整场停用，游戏不受影响 |

### 提示（8 项）

1. **MPB 残留是明示的设计决策**：`Restore()` 只把材质当前原值写回块内，从不清空整块（Unity 2021 无单属性删除 API，且需保护同槽其他属性）。渲染结果与原版完全等价（探针证实 `rendererStateRestored=True`）；仅当未来另装写全 Renderer 级 MPB 的插件才可能叠加干扰——当前游戏没有任何 MPB 写者（全反编译代码 grep 零命中）。
2. **FailSafe 不调用 `Assets.Dispose`**：部分加载成功的 Preview/图集纹理滞留到 `OnDestroy`，总量 < 2MB，整场一次，可忽略。
3. **真实鼠标点击路径（OnGUI → Select → GetAtlas 合成 + 写盘）未经原生验收**：`GUI.Button` 只在 MouseUp 事件返回 true，不存在 OnGUI 多事件重复合成；单次合成为毫秒级。QA06/07 经 `ConfigurePreview` 走的是同一 `Select`，纹理合成路径已被原生验证，仅剩 IMGUI 事件触发这一段。
4. **发布版与原版共用存档 profile**（仅 `--qa` 才改 company/productName）：MOD 不写存档，56 个真实存档文件哈希零变化已验证；属设计决策。
5. **版本指纹耦合**：字段名/属性名/材质布局仅对本构建成立；游戏更新后 Weaver 对指纹不符直接拒绝构建——是"不能用"而非"静默坏"，方向正确。
6. **Boat5 破冰器/彩旗复用 Boat4_Mat 共享材质**：若用材质写入会跨 Renderer 串色——MOD 恰好用 per-renderer MPB，已规避，记为设计正确性确认。
7. **措辞修正 ×2**：`flagMeshRenderers` 精确类型是 `List<SkinnedMeshRenderer>`（MOD 按 `IEnumerable` 遍历，兼容）；图集下部 76 行实际由独立的 FlagPole 网格使用而非旗面（MOD 保留该区域的策略仍正确且保守，仅 `AtlasLayout.cs:10` 注释措辞不准）。
8. **原版自身缺陷面**：存档 `BoatFlagStyle > 7` 时原版 `flagMaterials[style-1]` 会越界抛异常（`PlayerColorCustomizer.cs:127`）——原版即如此，异常发生在钩子之前，MOD 不改变该行为。

## 三、已核验无问题的关键方面（节选）

- **注入时序**：钩子织在 `RefreshBoatFlag()` 的 `ret` 之前、游戏自身读完 `flagMeshRenderers` 并 ForEach **之后**；字段初始化器 + Unity 反序列化远早于此。列表为 null 时游戏自己会先 NRE，轮不到 MOD。
- **IL 安全**：注入点栈净变化为 0；`MaxStack` 不变；含异常区段的方法直接拒绝织入；所有指向旧 `ret` 的分支/switch 重定向正确；审计反向断言无分支跳过钩子。
- **幂等与打包**：输入指纹必须是原版、AssemblyRef 查重、输出 `CreateNew` 禁覆盖；发布包内两 dll 哈希与 staging/审计三方一致；355 个原始游戏文件零变化，新增文件恰为预期 7 项；`Contents` 全程只读。
- **线程安全**：两个钩子仅由 `OnEnable` 与 `GameEvents` 事件在主线程触发；MOD 全部 Unity API 均在主线程。
- **MPB 语义**：游戏换色写 `materials[0].SetColor`、换旗整体换 `.material`，从不写 MPB；MOD 的 MPB 覆盖优先级高且不随材质替换丢失；游戏每次改色/换旗后钩子同栈立即重同步，错误基线不会被固化。
- **纹理生命周期**：`CopyReadable`/`GetAtlas`/`Dispose`/`PruneAtlases` 的 GetTemporary/ReleaseTemporary、`RenderTexture.active`、`GL.sRGBWrite` 全部 finally 配对；失败路径销毁半成品。
- **色彩空间**：Linear/Gamma 两种模式下 sRGB 字节往返均守恒；双线性在 sRGB 空间混合的轻微色偏对像素画旗面不可察觉。
- **装备机制兼容**：未装备旗帜时游戏 SetActive(false) 的是 FlagAccessory 父对象，MOD 不动 enabled/SetActive，对非激活 Renderer 写 MPB 合法，QA 已在 style=0 下原生读回验证。
- **生命周期**：切场景玩家船常驻不销毁；回标题/读档重建时 OnEnable 重新触发钩子注册；买新船是 5 档子模型 SetActive 切换，全部早已注册；死 Renderer 每 10 秒修剪；NPC 船不挂 PlayerColorCustomizer，永远不会被 MOD 碰到。
- **存档完整**：56 个真实存档文件哈希零变化；Steam 走官方 local-development 机制。
- **回归测试**：67 项纯托管测试全绿，含真实 manifest 与三张 1536×1024 PNG 头校验。

## 四、建议（仅建议，未做任何修改）

1. **补齐 M2**：在隔离 QA 档做一次「画匠处实际装备旗帜 → 选皮肤 → 航行观察 + 离屏截图」的原生回归，覆盖旗帜功能最后一环。
2. **修复 M1**（下次代码改动时）：`Bind` 改为全成功后一次性提交（先全部读到局部变量，最后统一赋值），消除半初始化态。
3. **修复 M3**：`build_local.py` 增加"源码 mtime 晚于 dll 则拒绝/重建"的只读检查。
4. **顺手修复 L3/L4**：`RegisterField` 先建 overrides 再入集合；FailSafe 状态下禁用原版行的 persist 写盘。
5. **文档措辞**：修正 `AtlasLayout.cs:10` 关于"下部 76 行是旗杆"的注释（实为独立 FlagPole 网格区域）。
