# DREDGE 天气类型与机制边界

日期：2026年10月17日。范围：本文件夹原始 `Contents/`，不包括 `output/` 外观副本。

本包有 **15 个 WeatherData 预设：13 个具有正随机权重的日常候选，2 个随机权重为零的终局特殊预设**，其中包含冰区天气。原版天气并非只有画面效果：海浪参数参与船速阻力和浮力计算，切换接口还会更新存档状态。因此，后续若要求保持原版机制，应研究独立的画面覆盖层，不能直接把原版天气切换函数当作纯外观开关。

本轮仅完成静态研究与本地证据整理，没有启动游戏、修改原包或存档，也没有开始实现天气功能。

## 原版天气清单

以下中文为便于理解的说明；内部名称来自原包。时长是预设的游戏小时数，不是现实时间，也不保证不被区域触发或剧情提前切换。

| 中文说明 | 原包内部名称 | 预设时长 | 自然抽选条件及特点 |
|---|---|---:|---|
| 晴朗，极少云 | `Clear` | 4小时 | 全部区域；无降水 |
| 晴好，少量云 | `Fine` | 6小时 | 冰区以外；也是主场景默认回退天气 |
| 多云 | `Cloudy` | 8小时 | 冰区以外；无降水 |
| 小雨 | `LightRain` | 8小时 | 冰区以外；无周期性闪电 |
| 中雨 | `MediumRain` | 8小时 | 冰区以外；无周期性闪电 |
| 大雨 | `HeavyRain` | 6小时 | 冰区以外；无周期性闪电 |
| 中等雷暴 | `MediumStorm` | 8小时 | 冰区以外；中雨配置加闪电 |
| 强雷暴 | `HeavyStorm` | 6小时 | 冰区以外；大雨配置加更密集闪电 |
| 极光 | `Aurora` | 6小时 | Stellar Basin 或 Pale Reach，夜间抽选 |
| 小雪 | `LightSnow` | 8小时 | 仅冰区 Pale Reach |
| 中雪 | `MediumSnow` | 8小时 | 仅冰区 Pale Reach |
| 大雪 | `HeavySnow` | 8小时 | 仅冰区 Pale Reach |
| 极光伴雪 | `AuroraSnow` | 6小时 | 仅冰区，夜间抽选 |
| 终局极光 | `FinaleAurora` | 6小时 | 权重0，不参与正常随机抽选 |
| 终局风暴 | `FinaleStorm` | 6小时 | 权重0，不参与正常随机抽选 |

`DataLoader` 在原始启动场景的加载标签确为 `WeatherData`；该 Addressables 标签精确指向这15项，和天气资源包内的15个实例一一对应。调试命令帮助仍写着 `clear, fine, cloudy, dark`，不能代表本包完整清单。

两项终局预设也有实际引用：原场景的 `SignalReceiver`（pathID 121838）在两个事件中调用 `FinaleCutsceneLogic.TransitionToWeather("FinaleStorm")` 与 `TransitionToWeather("FinaleAurora")`。因此“终局专用”有序列化调用证据，未仅依据名称推断。此处不展开剧情内容。

参数进一步区分了雨和雷暴：`MediumRain` 与 `MediumStorm` 的降雨发射率同为800，海浪陡度同为0.125；后者的闪电间隔参数为15至25秒。`HeavyRain` 与 `HeavyStorm` 对应2000、0.15，后者间隔为5至10秒。这里的发射率是粒子系统参数，不是现实降雨量；闪电间隔也不等于已经实测的精确出现间隔。

自然抽选先按区域和昼夜筛选，再按权重随机选择。区域位掩码64表示 Pale Reach，68表示 Stellar Basin 与 Pale Reach，-65排除 Pale Reach。极光的夜间标记约束抽选时刻；主场景的极光触发器也受到 `SceneTimeResponder.onWhenNight=1` 的启停控制。已生效的天气不会仅因天亮就立即重新抽选。天气资源存在也不替代原版的 DLC 区域权限。

## 雾与海龙卷属于另外的系统

场景雾由 `FogController` 和区域属性、时段曲线控制；会追踪玩家、响应灯光并影响理智的雾类实体另由 `FogDevil` 等组件控制。海龙卷使用 `WaterspoutWorldEvent`，命中路径调用碰撞伤害处理，并可概率加入物品。这些不能和15个 WeatherData 预设混为一类，也不能为了“天气好看”而关闭对应危险或事件。

[海龙卷代码](evidence/weather-2026-10-17/mechanics-decompiled/WaterspoutWorldEvent.cs)中的 `OnPlayerHit` 是明确的玩法路径。天气、海龙卷和夜间雾可能同时出现，但不是同一个开关。

## 天气控制代码与实际影响

| 入口 | 本包观察到的行为 | 对后续功能的影响 |
|---|---|---|
| `DataLoader.Load`、`OnWeatherDataAddressablesLoaded` | 按标签加载 WeatherData，建立 `allWeather` | 保留原版资源列表与加载流程 |
| `WeatherController.PickNewWeather` | 区域、昼夜筛选后按权重随机抽选 | 不能以锁定原版天气来实现纯画面模式 |
| `WeatherController.Update` | 根据游戏时间检查持续时长；检查区域有效性；渐变并输出画面、音效与浪参数 | 主场景渐变参数为15秒；不能整体跳过该方法 |
| `WeatherController.ChangeWeather` | 更新当前天气，并写 `SaveData.Weather` 和 `WeatherChangeTime` | 这是会改变游戏状态的接口；不等于调用时立即写盘 |
| `WeatherController.Update → WaveController.Steepness` | 同时更新画面海浪与供物理使用的海浪陡度 | 两者必须区分，不能把整个预设替换称为纯视觉 |
| `PlayerController.FixedUpdate` | 第192至195行将海浪陡度乘进水平阻力，再对刚体施力 | 改该数值会影响实际航行 |
| `BuoyantObject.FixedUpdate` | 用海浪位移计算浮力、重力和阻力 | 改海浪可能改变船体物理表现 |
| `TimeController.RecalculateSceneLightness` | 云量和云暗参与场景明暗判定；另有物体启停响应 | 即使只改云，也应避开原控制字段，先确认输出层边界 |
| `StingerAudio` | 读取天气的 `forbidStingers` | 原版天气还控制部分环境音效 |
| `WeatherTrigger`、`FinaleCutsceneLogic` | 区域触发或剧情直接请求天气变化 | 保留剧情与区域触发的优先级 |

关键位置：[天气输出](evidence/weather-2026-10-17/mechanics-decompiled/WeatherController.cs)、[船速阻力](evidence/weather-2026-10-17/mechanics-decompiled/PlayerController.cs)、[浮力](evidence/weather-2026-10-17/mechanics-decompiled/BuoyantObject.cs)、[场景明暗](evidence/weather-2026-10-17/mechanics-decompiled/TimeController.cs)。

主场景还包含多云、极光和雨天的区域触发器。盖尔悬崖中一个对象虽然名叫 `WeatherTrigger [HeavyRain]`，实际序列化引用是 `MediumRain`，说明对象名称不能替代引用核对。详见[实际天气引用](evidence/weather-2026-10-17/assets-weather-references.json)。

`WeatherParameters` 没有风速字段；`_wind` 是控制器独立值，不能仅因预设叫“风暴”便假定它会修改风速。在主程序集已检索的代码中，未见雨雪字段直接进入鱼类或理智计算的代码链，但这不等于整套天气不影响玩法。

## 后续设计边界

建议先把“改变眼前的天气画面”和“改变游戏实际天气”分开。若继续实现符合当前约束的版本，应保留原版天气抽选、持续计时、存档、物理海浪、理智、事件、时间和剧情，只在经过核实的显示层覆盖云、降水或极光，并提供恢复原版的方式。这仍是待验证方案，不是已完成的安全功能。

视觉雷电也不能随意复用原版 `Lightning.Emit`：天气、雷电、鱼的大小或异化、世界事件都使用 `UnityEngine.Random`。新增或减少随机调用可能改变后续抽签顺序，这是基于调用链的设计风险推断，尚未做运行实验。独立视觉组件需要自己的随机状态，且不能中断原版随机消耗。

雾与能见度会影响玩家实际观察，即使数值逻辑保持不变；需要保留危险提示，并在真实场景检查。剧情切换、暂停、重载和恢复原版也须验证。上述事项属于后续实现验收，本轮没有把它们记为通过。
