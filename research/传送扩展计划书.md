## 0. 功能概述与总体架构

**功能**：在原生「Manifest 传送 / 传送锚点」之外，新增一个目的地传送轮盘——按住热键打开轮盘、方向选择目的地、松开确认传送。目的地为地图四角流浪商人码头、冰川 DLC 商人、油井 DLC，共 6 个。

**总体架构**（与现有外观管线同形）：

| 层 | 改动 | 说明 |
|---|---|---|
| Weaver | 白名单 +1 个引导钩子 | 与现有两钩子完全同形的 postfix 引导（`ldarg.0; call static void Bootstrap.X(object)`），选每局必然执行的无 EH 小方法；**无需新型注入形态** |
| 运行时组件 | `Jinke.DredgeSkins.dll` 新增 4 个类 | `TeleportController`（引导与门控）、`TeleportDestinationCatalog`（目的地发现与落点计算）、`TeleportWheelUI`（轮盘）、`TeleportSettings`（开关持久化） |
| 配置 | `streamingAssetsPath` 下 `teleport.json` | 目的地表：id、显示名、落点偏移、图标、DLC 资格 |
| 设置 | 扩展 `settings.json` sidecar | 总开关 + 各目的地开关 + 理智消耗 + 冷却；**必须同步扩 `SkinJson.RequireKeys` 白名单**，否则旧读取器整体回退默认值 |
| 原生资产 | 0 修改 | 不改 SaveData、不改 prefab、不改 Addressables |

关键约束继承：组件不引用 Assembly-CSharp（全反射窄接口）、不用 `UnityEngine.Random`、构建只产出 `output/` 副本、输入 DLL 哈希钉死 `a071ff…4729`。

## 1. 启用功能的开关设计

### 1.1 持久化 schema（sidecar，与皮肤设置同文件）

```json
{
  "schemaVersion": 1,
  "boat": "original",
  "flag": "original",
  "teleport": {
    "enabled": true,
    "sanityCost": -0.4,
    "cooldownDays": 0.0,
    "destinations": {
      "pontoon-ts": true, "pontoon-sb": true, "pontoon-ds": true,
      "pontoon-gc": true, "pontoon-tpr": true, "the-iron-rig": true
    }
  }
}
```

读取规则与现状对齐：文件不存在 / `teleport` 节缺失 → 全部默认（总开、六目的地全开、理智 -0.4、无冷却）。扁平、缺省即安全；字节量远低于 4096 上限。

### 1.2 游戏内开关界面

- 新快捷键 **F9** 打开「传送设置」小窗，复用 SkinWindow 已验证的模式：暂停门控（仅原生暂停时可开）、输入持有/恢复（`PauseUiGuard.HoldInput` 式：临时禁用 `DredgeInputManager` 派发，关闭时还原）、纯键盘操作（方向键 + 回车开关 + Esc 关闭）。
- 内容：总开关一行 + 六个目的地各一行 + 理智消耗档（0 / -0.2 / -0.4 / -0.5）+ 冷却档（无 / 0.5 天 / 1 天）。确认即写 sidecar，**即时生效**（TeleportController 监听设置变更事件，不要求重启）。
- 未安装 DLC 的目的地在设置窗中灰显并标注「未拥有 DLC」，不隐藏——便于诊断资格判定问题。

### 1.3 运行时门控（功能总开关之外的软开关）

传送轮盘仅在以下全部满足时可打开：

1. `teleport.enabled == true`
2. `Player.IsDocked == false` 且动作层 == `ActionLayer.BASE`（停靠时 `PlayerFreezePositionHack` 每帧锁位置，必须避开；`Player.cs:108`、`PlayerFreezePositionHack.cs:22-41`）
3. 非暂停、非对话、非弹窗、非过场（订阅 `OnDialogueStarted/Completed`、`OnPopupWindowToggled`、`OnCutsceneToggled`）
4. `Player.IsAlive`、不在传送协程中（`OnTeleportBegin/Complete` 自锁）
5. **终局锁**：订阅 `OnFinaleVoyageStarted`（比 cutscene 更早，广播时冻结时间并禁存档）与 `OnFinaleCutsceneStarted`，一旦触发永久禁止传送，与原生 `AbilityBarUI` 的 `IsCastingForbidden` 行为一致（`AbilityBarUI.cs:97-100`）

### 2.2 落点算法（运行时发现，不写死坐标）

**不信对象名、不信硬编码坐标**——运行时用反射懒发现：

1. `FindObjectsOfType` 反射取 `Dock` 类型全部实例 → 读 `Data.Id` 匹配上表六个 id；
2. 在同对象（或子对象）取 `DockPOI.dockSlots`（`Transform[]`）——这就是原生停靠流程使用的精确水面泊位（`DockPOIHandler.cs:156-179` 同款取法），**天然在水里，无需陆地校验**；
3. 落点 = 任选一槽位 `dockSlots[i].position` 的 XZ + `teleport.json` 中每目的地的可调偏移（建议默认沿槽位 forward 背向码头方向 3 m，避免传送即贴脸触发 POI 提示）；
4. 朝向 = `dockSlots[i].forward`，取背向码头实体的一侧；
5. Y 不用算：`PlayerTeleport.DoTeleport` 内部自动叠加波浪位移并按 `BuoyantObject.objectDepth` 修正吃水（`PlayerTeleport.cs:46-52`）；
6. 可选校验：`PlayerZoneDetector.GetZoneForPoint(落点)`（公开静态，`PlayerZoneDetector.cs:40-53`）确认落在预期 ZoneEnum 区域（如 TPR → PALE_REACH=0x40），失败则拒绝传送并提示，防止资产改版后错位。

### 2.3 DLC 资格过滤

- `GameManager.EntitlementManager`（公有属性）→ `GetHasEntitlement(Entitlement)`，`DLC_1=3 / DLC_2=4`（`EntitlementManager.cs:49-59`、`Entitlement.cs:1-8`），反射调用，未登记时安全返回 false。
- 双重保险：未购 DLC 时场景根 `DLC1`/`DLC2` 会被 `EntitlementDependantObject` 整根销毁，懒发现本来就找不到——资格检查主要用于设置窗灰显与轮盘项隐藏。
- 轮盘中未拥有的 DLC 目的地**不显示**；设置窗中**灰显**（诊断友好）。

## 3. 目的地选择轮盘 UI（复用技能轮盘）

### 3.1 路线选择：视觉克隆 + 自写逻辑（推荐）

原生轮盘不可直接扩展：`AbilityRadial` 的 wedge 列表是 prefab 序列化摆好的（`AbilityRadial.cs:24`），格数硬编码 10（`:100-123`）。整克隆运行时实例存在 8 项已查实障碍——输入双注册（按 E 两轮盘同开）、`Start` 污染当前选中技能、共享 `IsShowingRadialMenu` 单例串扰、`OnDisable` 误关原生轮盘、`SelectPlayerAbility` 连锁写 `SaveData.LastSelectedAbility`、伪造条目须写 `SaveData.unlockedAbilities`（存档污染）、`ActiveAbilityInfoPanel` NRE 需预注册映射、`SetAbilityUnseen` 写存档。

**因此采用「复用轮盘的形，自建轮盘的魂」**：

- **克隆视觉骨架**：运行时找到原生 AbilityRadial GameObject，`Instantiate` 一份，**销毁克隆体上的 AbilityRadial/AbilityRadialWedge 逻辑组件**，保留 wedge 布局、图标 Image、selectionWedge、中央标题栏等纯视觉元素。6 个目的地用其中 6 格，多余格隐藏。
- **自写交互**：复刻原生手感——打开时 `Time.timeScale = 0.3f` 慢动作 + DOTween 0→1 缩放（0.35s、OutExpo、unscaled）+ 开关音效（反射取原生 openSFX/closeSFX/selectSFX 播放）；鼠标方位角或方向键量化 60°/格（6 格）。
- **确认语义自定（原生没有，需补）**：原生是「选中即切技能、关轮盘后再按技能键施放」；本功能做成**按住开、移动选、松开即传送**——与 `radialTriggerMode` 按住模式的肌肉记忆一致，少一次按键。
- **零存档污染**：不碰 `SaveData.unlockedAbilities` / `LastSelectedAbility` / `abilityHistory`（冷却自管 key 除外，见 §5.2），不触发 `SelectPlayerAbility`。

### 3.2 输入方案

- **第一期（键盘）**：组件 `Update` 用旧版 `Input.GetKey/GetKeyUp` 实现按住/松开状态机（`SkinController.cs:141-142` 同款先例）。默认热键 **T**（Teleport；与现有绑定无冲突，可配置）。打开期间禁用 `DredgeInputManager` 派发防止操作穿透（`PauseUiGuard.cs:113-126` 模式）。
- **后续增强（手柄）**：反射创建 InControl `PlayerAction` 挂 `ActionLayer.BASE`，获得手柄支持与改键跟随——反射成本高，列入 M3 候选。

## 4. 传送动画（复用原生全套演出）

### 4.1 调用方式

```
PlayerTeleport.Teleport(落点XZ, sanityChange: 配置值(默认-0.4), abilityToUse: null)
```

- 特效、专用相机、全身震动、音效**全部来自原生 `PlayerTeleport` 实例自身的序列化字段**（`PlayerTeleport.cs:8-27`），与 `abilityToUse` 无关——**传 null 即与传送锚点完全一致的原生演出**，且不会误入 Manifest 的 350 单位成就判定。
- 必须调玩家身上的原生实例（`Player.cs:52`），其引用只有原生 prefab 齐全。

### 4.2 原生演出全流程（`DoTeleport` 逐阶段，自动获得）

1. 传送特效粒子重启 → **船模立即隐藏** → 全身震动 → 免伤开启 → 施法音效；
2. 广播 `OnTeleportBegin` → 动作层切 NONE（锁输入）→ 禁移动 → 切换传送专用 vcam；
3. 落点波浪/吃水校正 → preHold 等待 → 相机 `OnTargetObjectWarped` 防插值 → **改写船位置** → 理智变化；
4. hold 停留（船仍隐藏）→ 船模恢复 → 二次震动 → 恢复移动/关免伤 → 相机与动作层还原 → 广播 `OnTeleportComplete`。

附带原生联动（无需额外处理）：落地后 `WeatherController` 按新区域重抽天气（传冰川自动切雪）、利维坦追击立即结束、海怪侦测重置、拖网刷新。**原生无屏幕淡入淡出**，不额外添加，保持原味。

### 4.3 时序陷阱（必须遵守）

`preHoldTimeSec`/`holdTimeSec` 两段等待走 **scaled 时间**——若在轮盘打开的 0.3 倍慢动作中调用，整个传送会被拉长 3.3 倍。**流程必须是：松开热键 → 关轮盘（恢复 timeScale=1）→ 再调 `Teleport()`**。

## 5. 其他要点

### 5.1 理智消耗

默认 -0.4（与 Manifest 一致；锚点先例为 -0.5，锚点是回理智传负值——注意本项目 sanityChange **负值为扣除**，符号语义以 `PlayerTeleport.cs:59` → `PlayerSanity.ChangeSanity` 为准，实施时用 NativeProbe 实测一次确认方向）。低理智无单次惩罚，但会推近幻觉/袭击事件刷出窗口（`WorldEventManager.cs:331-353` 等），设置窗提供 0 / -0.2 / -0.4 / -0.5 四档。

### 5.2 冷却（可选，默认关）

- 原生冷却单位是**游戏天数**，存在 `SaveData.abilityHistory`（`Dictionary<string,float>`，key=能力名小写）。
- 直调 Teleport 绕过 AbilityBarUI 不写历史。设计：默认 `cooldownDays=0` 完全不写；开启后自管 key（如 `"jinke-teleport"`），施放前查 `TimeAndDay - history < cooldown` 拒绝，施放后写入。
- ⚠️ 这是本功能**唯一**写 SaveData 的路径，默认关闭；开启时需在文档明示。不与 Manifest 共享 key，避免干扰原生技能。
- Manifest AbilityData 的 cooldown 数值为序列化资产，反编译不可见——若想做「与原生 Manifest 同冷却」，需运行时反射读取（未确认，列入开放问题）。

### 5.3 存档与兼容原则

- 不写 `SaveData`（冷却关闭时零写入）；自定义 id 不进原档；设置全在 sidecar。
- DLC 目的地运行时资格过滤 + 场景对象懒发现，未购 DLC 自动缺项；「存档标记用过 DLC 但当前无资格」由原生 `StartupLoader` 拦截，与组件无关。
- 游戏更新后补丁不沿用：输入程序集 SHA-256 钉死 `a071ffebe51514af5f661055f126a5041acda127623ee7c681c6ef2233a24729`。

### 5.4 测试计划（沿用项目四层）

1. **Weaver 单测**：新引导钩子走既有 fixture（分支/switch/短跳转/EH 拒绝/指纹拒绝），语义审计证明「9,375 方法体中仅目标方法多了引导调用」；
2. **托管断言**：`teleport.json` 与 settings schema 解析边界、设置往返、目的地目录匹配逻辑（模拟 id 表）、门控状态机真值表；
3. **NativeProbe**：反射链验证（EntitlementManager / DockPOI.dockSlots / PlayerTeleport 实例 / GetZoneForPoint 返回值）、理智符号方向实测；
4. **原生 QA**：键盘路径全链路（开轮盘→选→传送→落点→天气切换→联动事件）；六个目的地逐一实传；DLC 资格开关两组对照；终局锁验证。**已知盲区**：CUA 合成鼠标点击不被 Unity 接受，鼠标选格以人工验证为准；手柄不验（第一期不支持）。

### 5.6 风险与回滚

| 风险 | 等级 | 缓解 |
|---|---|---|
| 轮盘克隆视觉元素含隐藏依赖（引用原生状态） | 中 | M1 先静态截图验证克隆体渲染，再接输入；兜底退化为 SkinWindow 式列表窗 |
| TPR 区域存在「假定从海上抵达」的剧情触发器 | 中低 | 冰川目的地默认开关独立；M0 后专项排查 Yarn 对话触发器 |
| 落点槽位在资产改版后偏移 | 低 | 落点运行时读取 + ZoneEnum 校验 + JSON 偏移可调 |
| 设置白名单遗漏导致旧组件读新文件回退 | 低 | `RequireKeys` 扩展与托管断言覆盖 |
| timeScale 陷阱导致传送拉长 | 已设计规避 | §4.3 流程约束写进 M1 验收 |

回滚：设置窗「总开关关」即功能全熄；`output/` 副本外原包不动；sidecar 删除即恢复默认。

### 5.7 开放问题（实施前需关闭）
