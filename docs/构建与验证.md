# 构建与验证

## 不依赖游戏的检查

需要 Python 3 和 .NET 10 SDK，在仓库根目录执行：

```sh
python3 -m unittest discover -s tools/tests -p test_build_merchant_travel.py -v
dotnet run --project src/Painter/AppearanceTests/Appearance.Tests.csproj
```

Python 测试使用临时 fixture，默认跳过 opt-in 真实构建；不要设置 `JINKE_MERCHANT_BUILD_INTEGRATION=1`，除非任务要求。外观测试使用游戏和 Unity 替身。这些检查不启动 Unity，不证明真实输入、GPU 效果或玩家存档可用。

## 本地重建

目标系统为 macOS。当前运行隔离合同的 `src/MerchantTravel/ProfileContract.cs` 将 OutputRoot 固定为原工作区 `/Volumes/T7 Shield/渔帆暗涌REA/output`。其他位置的克隆可阅读和运行上面的离线检查，但不能直接当成可移植的生产运行目录；迁移路径需要另行审查隔离合同，本轮未改此常量。下面重建步骤面向原工作区。

自行从拥有的正版安装准备 app 的 `Contents/` 到原工作区根目录，保持原样，不上传。原 `Assembly-CSharp.dll` 的 SHA-256 必须为：

```text
a071ffebe51514af5f661055f126a5041acda127623ee7c681c6ef2233a24729
```

使用 .NET 10 SDK、Python 3 与构建脚本依赖 UnityPy。Python 环境需能执行 `import UnityPy`；阅读源码无需安装游戏依赖。签名及隔离检查使用 macOS 工具。游戏更新后需重新核对指纹与接口。

在明确授权构建的任务里，使用尚不存在的 app 名称：

```sh
python3 tools/build_painter.py --name 'DREDGE Painter Fresh.app'
```

构建器 fresh 编译当前源码、校验固定十七处补丁、复制到新副本、签名并生成启动器；不启动游戏或迁移进度，已有目标拒绝覆盖。详细合同见 `src/Weaver/README.md`、`src/MerchantTravel/README.md` 与 `research/油漆匠接入与验证.md`。

旧 `tools/tests/test_build_local.py` 需要专用 CLI 参数及真实游戏 DLL，不能用全目录 unittest discover 代替它的入口。Weaver 测试虽然使用合成程序集，也会检查真实 Contents 工作区，不能在无游戏副本中跑完全套。MerchantTravel 规则、FishingTuning、Yarn 对话与原资源货舱模拟等测试同样需要真实游戏 DLL 或资源。真实启动、进度复制与手工验收属于另外的授权范围。
